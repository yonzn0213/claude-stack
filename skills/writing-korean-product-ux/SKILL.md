# 한국어 제품 UX·문구

## 핵심

사용자가 설명 없이 화면만 보고 할 일과 결과의 뜻을 알아야 한다. 토스 앱인토스 가이드에서 가져왔지만 한국어 소비자 앱·웹 전반에 쓴다. 고객사 업무 문서·메일 문체는 이 스킬이 아니라 CLAUDE.md의 고객 응대 문체를 따른다.

## 문구 쓰는 법

모든 문구는 아래 모양으로 쓴다.

| 자리 | 이렇게 쓴다 | 예 |
|---|---|---|
| 문체 | 해요체. `되어요` 대신 `돼요` | 저장했어요 |
| 버튼 | 누르면 생기는 일을 동사로 | `확인` → `결과 보기`, `저장` → `오늘 기록 저장하기` |
| 다이얼로그 왼쪽 버튼 | 항상 `닫기` (`취소`는 하던 일이 취소된다고 오해함) | 삭제할까요? [닫기] [삭제하기] |
| 결과(점수·등급·유형) | 숫자 + 뜻 + 바뀐 이유 | 72점, 지난주보다 조금 높아요. 기록한 날이 하루 늘었어요. |
| 빈 화면 | 왜 비었는지 + 채우면 생기는 일 | 아직 기록이 없어요. 첫 기록을 남기면 여기에 보여 드릴게요. |
| 못 쓰는 기능 | 할 수 있는 길을 긍정형으로 | 데이터 내보내기는 프로 플랜에서 할 수 있어요. |
| 오류 | 무슨 일이 있었나 + 다음 행동 | 인터넷이 끊겨서 저장하지 못했어요. 연결되면 다시 저장해 주세요. |
| 능동형 | 우리가 한 일은 `했어요` (`됐어요` X) | 기록을 지웠어요 |
| 경어 | `~시`·`께`·`계시다`·`여쭈다`를 빼고 캐주얼하게 | 확인하시겠어요? → 확인할까요? |
| 명사 나열 | 한자어 명사를 동사로 풀기 | 기록 저장 완료 → 기록을 저장했어요 |

부정형은 정책상 막혔을 때(이유를 함께), 일부 기능만 안 될 때, 안심시킬 때만 쓴다.

## 화면 짜는 법

- 열자마자 가장 먼저 할 일이 보인다. 주된 행동은 화면 아래 고정 버튼 하나로 둔다.
- 입력란과 버튼은 쓰는 순서대로 놓는다. 같은 정보를 여러 번 받지 않는다.
- 일이 끝나면 완료 문구(토스트·완료 화면)와 다음에 누를 버튼을 보여 준다.
- 크기로 중요도를 나눈다. 제목·결과·설명을 비슷한 크기로 두지 않는다.
- 같은 역할은 모든 화면에서 같은 모양과 색이다. 색과 장식은 강조할 때만 쓴다.
- 빨간색은 실제 문제(법 위반, 돈 손해, 실패)에만 쓴다. 단순 안내는 회색이다.
- 입력이 바뀌면 결과에 바로 반영하고, 왜 달라졌는지 알려 준다.
- 출시 전 샘플 문구·임시 이미지가 남아 있지 않은지 본다.

## 하지 않는 것 (다크패턴)

들어오자마자 화면을 덮는 광고·동의 창, 뒤로 가기를 막는 동의 유도, 유도 버튼 말고는 나갈 길이 없는 화면, 예상 못 한 전면 광고, 애원·죄책감을 건드리는 문구.

## 상황별로 더 읽을 파일 (같은 폴더)

| 상황 | 파일 |
|---|---|
| 오류·토스트·확인 창·로딩·빈 화면·입력칸 문구를 쓴다, 문구를 다 쓰고 점검한다 | `korean-companies.md` (토스 라이팅 8원칙·에러 6원칙, 당근 SEED, 배민) |
| 결제·구독·해지·회원가입·개인정보 동의·팝업 반복이 있다, 접근성을 본다 | `korean-law-and-standards.md` (전자상거래법 다크패턴, 동의 안내서, KWCAG, KRDS) |
| 토스 미니앱(앱인토스)을 만들거나 검수 준비를 한다 | `apps-in-toss.md` (만들기 전 경쟁 앱 검색, 검수 규칙, TDS 값, SDK 함정) |

결제·구독·동의 화면이 있는데 `korean-law-and-standards.md`를 안 읽었으면 출시 전에 읽는다. 법 위반은 디자인 취향 문제가 아니다.

## 자주 틀리는 것

| 틀린 것 | 고친 것 |
|---|---|
| 다이얼로그 `[취소] [삭제]` | `[닫기] [삭제하기]` |
| `이번 주 점수는 72점이에요.` | 점수 뒤에 비교와 이유를 붙인다 |
| `무료 플랜에서는 ~을 이용할 수 없어요.` | `~은 프로 플랜에서 할 수 있어요.` |
| `데이터가 없습니다` | 해요체 + 이유 + 채우는 방법 |
| 버튼 `완료`·`확인`·`저장` | 동작이 드러나는 동사구 |
