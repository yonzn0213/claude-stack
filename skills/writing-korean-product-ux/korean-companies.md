# 국내 IT 기업이 공개한 UX·문구 규칙

2026-11-10 조사. 공식 1차 출처만 규칙으로 옮겼다. 외부 분석·검색 요약은 [참고]로 표시한다.
공개 자료가 없던 곳: 카카오·카카오뱅크·카카오페이·LINE·쿠팡·무신사·야놀자(소비자 앱 문구 가이드 미공개), 배민(공식 규칙 문서 미공개, 운영 인터뷰만).

## 문구 점검 질문 (토스 8가지 라이팅 원칙)

문구를 다 쓴 뒤 하나씩 묻는다.

1. 다음 화면에서 무슨 일이 생길지 힌트가 있나? 혜택만 말하고 다음 단계를 숨기면 불안하다.
2. 빼도 뜻이 같은 낱말이 있나? (글자 수가 아니라 의미 없는 낱말을 지운다)
3. 같은 말을 화면 안에서 반복하거나, 허전해 보여서 넣은 문장이 있나?
4. 사용자가 이미 아는 정보를 다시 말하나? 지금 확인할 것만 남긴다.
5. 소리 내어 읽어도 자연스럽나? 한 문장에 메시지 하나, 전문 용어 없이.
6. 행동을 강요하거나 겁주나? 선택권이 있다고 느끼게 중립적으로.
7. 나이·학력·업계에 따라 모를 말, 유행어, 은어가 있나?
8. 정보 뒤의 감정을 챙겼나? 예: 대출을 다 갚으면 축하한다.

## 오류 문구 (토스 에러 메시지 6원칙 + 시스템화)

1. 문구를 쓰기 전에 이 오류를 아예 없앨 수 있는지 먼저 본다. (예: 송금 목록에서 내 연락처를 빼서 "본인에게 보낼 수 없어요" 오류 자체를 없앰)
2. 설명이 길면 토스트 말고 다이얼로그. 급하지 않은 일에 빨간색을 쓰지 않는다.
3. 실패 사실만 말하지 않고 스스로 해결할 방법을 붙인다. 가능하면 해결 버튼(다시 시도, 고객센터 연결)까지.
4. 개발 코드·IT 용어·회사 쪽 용어를 쓰지 않는다.
5. 사용자 탓으로 쓰지 않는다: `비밀번호를 틀렸어요` → `김토스님의 정보가 아니에요` 처럼 상황을 말한다.
6. 반복되는 상황(점검, 네트워크, 기관 장애)은 템플릿 하나로 고정하고 은행명·시간 같은 값만 바꾼다. 우리 잘못인 오류도 해요체를 유지한다.

## 입력·완료 문구 [참고: 요즘IT의 토스 화면 분석]

- 입력 라벨을 질문으로: `받는 분` → `어디로 돈을 보낼까요?`, `금액` → `얼마나 보낼까요?`
- 사용자 시점의 말로: `출금 계좌/입금 계좌` → `~에서 / ~로`
- 완료는 결과를 문장으로: `이체가 완료되었습니다` → `엄마에게 5만 원을 보냈어요`
- 헷갈리는 입력은 나눈다: 받는 사람에게 보일 이름과 내 기록용 메모를 따로 받는다.

## 컴포넌트 고르는 법 (당근 SEED 디자인 시스템)

**확인 창(Alert Dialog)**
- 꼭 확인이 필요할 때만 쓴다. 버튼은 닫기 포함 2개까지, 둘 중 하나를 고르는 구조.
- 빨간 버튼은 삭제·작성 내용 사라짐·초기화처럼 되돌릴 수 없는 버튼에만. 닫기 버튼에는 쓰지 않는다.
- 바깥을 눌러도 닫히지 않게 한다. 라벨이 길면 버튼을 세로로 쌓는다.

**스낵바·토스트(Snackbar)**
- 방금 한 일의 결과부터 쓴다: `업로드를 완료했어요`. 한 문장이면 마침표를 생략하고, 두 문장 이상이면 모두 찍는다.
- 이중 부정 금지(`실패하지 않았어요` X).
- 기본 4초, 길면 더 길게, 누르고 있는 동안은 멈춘다. 화면에 하나씩만, 나머지는 차례로.
- 버튼은 1개, 1~2낱말 구체 동사(`되돌리기`, `목록 보기`). 추가·삭제처럼 중요한 변경에는 `되돌리기`를 준다.
- 결정이 필요하면 스낵바 말고 바텀시트·확인 창, 계속 보여야 하면 배너.

**결과 화면(빈 상태·성공·실패)**
- 그림 + 제목(핵심 한 줄) + 설명 + 다음 행동 버튼.
- 성공: 결과를 분명히. 실패: 원래 하려던 일을 이룰 다음 행동. 빈 상태: 무엇을 하면 되는지.
- 실패 화면 버튼 뜻을 나눈다: `뒤로`(고쳐서 다시) / `닫기`(창 닫기) / `돌아가기`(되돌릴 수 없을 때 홈 같은 안전한 곳) / `다시 시도`(같은 일을 바로 다시).

**로딩**

| 기다리는 시간 | 보여 줄 것 |
|---|---|
| 1초 미만 | 아무것도 안 보여 준다(깜빡임이 더 나쁘다) |
| 1~4초 | 스켈레톤 또는 빙글 도는 표시 |
| 4~10초 | 위 표시 + 무엇을 하는 중인지 |
| 10초 이상 | 진행률 + 예상 시간 |
| 1분 이상 | 진행률 + 백그라운드 처리 + 취소 |

**입력칸**
- 전화번호처럼 형식이 정해진 값은 칸을 쪼개지 말고 한 칸에 자동 서식으로.
- 일부를 가려야 하는 값(주민번호 뒷자리, 카드번호)만 칸을 나눈다.

## 운영 (배민 B컷 인터뷰)

- 문구와 디자인을 따로 승인받지 않고 디자인 리뷰 때 같이 본다.
- 오래 걸리거나 법적 안내가 있는 화면은 예상 시간을 먼저 알리고, 버튼에 실제 잰 시간을 약속한다: `2분 만에 끝내기`.
- 사용자에게 중요한 숫자를 보여 준다: 함께주문에서 "아직 메뉴를 안 고른 사람 수".
